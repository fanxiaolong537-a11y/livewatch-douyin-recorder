# LiveWatch v0.1.0 实际验收报告

日期：2026-11-14。结论：**源码核心测试通过，尚未满足 Windows EXE 与 GitHub 发布验收；不能作为 V1.0 全部完成交付。**

## 实际环境与结果

- Linux x86_64；Python **3.11.18**；Flet 0.85.3；StreamGet 4.0.10。
- 完整命令：`python -m pytest -q --junitxml=docs/test-results.xml`。
- 最终结果：**33 passed in 33.83s**。机器可读结果在同目录 XML。
- `python main.py --self-test`：imports=ok；FFmpeg、FFprobe、Node 三项均检测到。
- Windows 3.11 x64 依赖解析成功（uv 目标平台解析），**不是 Windows 安装/运行验证**。
- 用 FFmpeg lavfi 自行生成320×180、25fps视频及440Hz正弦音频；无第三方直播录像。测试包含真实文件读写、真实 FFmpeg/FFprobe 和本地 HTTP 服务。
- 首轮21项通过、6项失败：发现 Store.add 空参数调用 update 的错误；已修复并增加数据库异常回滚。随后27、28项测试通过，最终扩展到33项。
- Python 3.12 导出的初版间接依赖不支持3.11，已改用3.11实际安装并重新锁定，最终测试使用3.11运行。

## 明确未完成与已知问题

- 没有验证真实抖音、Windows发行包、托盘及自启动；不能保证当前平台兼容性。
- 不兼容MP4的编码只保留TS，未实现自动重编码。
- FFprobe/包扫描可以发现部分损坏，不代表所有帧均可解码；无逐帧完整解码验证。
- 异常关机后不会自动修复遗留录像；任务恢复为新会话。
- 长视频转封装超过120秒会超时，源文件保留。处理时间和容量上限需要Windows真实长时录制测试。
- 本轮使用秒级分段加速验证分段机制，没有进行真实30/60分钟长稳测试。
- 日志脱敏有自动化回归，但诊断中可能仍含个人自定义文件路径，用户分享前应检查。
